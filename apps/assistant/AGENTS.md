# Assistant

The app has one user, the owner, and stores only login, settings, push subscriptions, sealed mailbox logins, and what the models write (morning reports, to-dos). It never stores mail content: no bodies, subjects, sender addresses or snippets. Mail is read from IMAP when a job needs it and dropped after use. Keep it that way.

- Ports: the app is `node ../../scripts/get-worktree-port.mjs 300`, its PGlite database `… 2533`. `ASSISTANT_PORT=3000 pnpm dev` puts the app on 3000, the one localhost port the Google and Microsoft OAuth clients accept; stop `apps/web` first.
- `pnpm dev` starts a per-worktree PGlite database in `.assistant-db/`, migrates it, seeds one dev user, and sets local secrets, unless `ASSISTANT_DATABASE_URL` is set. Delete `.assistant-db/` to start over.
- Sign in as an agent: `pnpm --filter assistant assistant:session` while `pnpm dev` runs, then set the cookie it prints on `http://localhost` (a LAN host needs a Secure cookie). There is no sign-up: the owner's passkeys exist in production, and a lost passkey needs a passkey row written by hand.
- Vercel env: run `vercel link --project assistant --scope tuja-labs --yes` in `apps/assistant` once, then `vercel env run -e development -- <cmd>` there. The repo root is linked to `qingqi-dev`. A changed variable reaches production only with a new build, and the `ignoreCommand` in `vercel.json` cancels a Redeploy of a commit that did not change the app, so merge a change under `apps/assistant` instead.
- Data access: pass the user id from the session or the cron, never from a request body, and filter every query of a user table by `user_id` (`ownAccount` in `mail/accounts/own-account.ts` for one account). There is no row level security.
- Migrations: change `src/assistant/db/schema.ts`, run `pnpm assistant:generate`; write SQL drizzle cannot generate with `pnpm exec drizzle-kit generate --custom --name <name>`. Never edit or delete an applied migration: production has run them all. Vercel runs them on preview and production builds. Previews use the Neon branch `preview`, which `assistant-reset-preview-db.yml` resets from production every day, without sign-in sessions, mail accounts and push subscriptions.
- Crons: add the route under `src/app/api/cron/`, build it with `makeUserCronHandler`, and list it in `vercel.json`. The proxy lets `/api/cron/*` through without a Referer; the handler checks `CRON_SECRET`.
- Mail: `src/assistant/mail/`. IMAP goes through the `MailboxSession` interface (`imap/types.ts`); `imapflowConnector` is the real one, `createFakeMailServer` the in-memory one for tests. Never test against a real mailbox. Log in with `openMailboxSession` (`accounts/open-mailbox-session.ts`): when the server refuses an OAuth token, it refreshes the token and tries once more before the account goes to `reconnect`. A connect and 立即检查 run `checkAccount`, which reads the folder list and no mail.
- Local OAuth: Google and Microsoft accept only `https://assistant.qingqi.dev` and `http://localhost:3000` callbacks, so run `vercel env run -e development -- env ASSISTANT_PORT=3000 pnpm dev` to get the client ids.
- Organise: `src/assistant/organise/`. The 15-minute cron `organise` runs only for users with `user_settings.organise_enabled`. For each account it reads INBOX oldest first (`BODY.PEEK`), asks Haiku for a folder (`organise-prompt.ts`; `organise_notes` are the user's words), adds `\Seen`, then MOVEs the mail. It can make up to 3 top-level folders per account per run (`candidate-folders.ts` cleans and matches the names). Mail without a usable answer stays in INBOX for the next run. Never delete; MOVE only, no copy-and-expunge fallback; a server without MOVE gets `write_error_code` `move_unsupported`.
- Morning report: `src/assistant/report/`. The hourly cron `morning-report` builds a user's report from their `digest_hour` on (local time, `due-report-date.ts`) once per local day. It reads the mail of the previous local day from IMAP, read-only (`read-day-mail.ts`; Gmail only All Mail, other servers every folder but Sent, Drafts, Trash, Junk and the virtual ones, `report-folders.ts`), gives it and the open to-dos to Sonnet (`report-prompt.ts`, raise its `version` when it changes), and stores only `morning_reports` and `todos`. When no mailbox can be read, there is no model, or the call fails, it stores nothing and the next hour tries again; from 23:00 local it stores a report that says so (`build-morning-report.ts`). Pages: `/` (latest report), `/todos`, `/reports`. Web Push needs both VAPID env vars; the service worker registers in production builds only, so push cannot be tried under `pnpm dev`.
- Calendar is a later phase. The CalDAV code of the first try was deleted; git history has it.
