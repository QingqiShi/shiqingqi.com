# Assistant

- Ports: the app is `node ../../scripts/get-worktree-port.mjs 300`, its PGlite database `… 2533`. `ASSISTANT_PORT=3000 pnpm dev` puts the app on 3000, the one localhost port the Google and Microsoft OAuth clients accept; stop `apps/web` first.
- `pnpm dev` starts a per-worktree PGlite database in `.assistant-db/`, migrates it, seeds one dev user, and sets local secrets, unless `ASSISTANT_DATABASE_URL` is set. Delete `.assistant-db/` to start over.
- Sign in as an agent: `pnpm --filter assistant assistant:session` while `pnpm dev` runs, then set the cookie it prints on `http://localhost` (a LAN host needs a Secure cookie).
- Invite a person: `pnpm assistant:invite-link --name <name>`; `--user <id>` makes a recovery link. Against production: `vercel env run -e production -- pnpm assistant:invite-link --name <name> --allow-remote` from `apps/assistant`.
- Vercel env: run `vercel link --project assistant --scope tuja-labs --yes` in `apps/assistant` once, then `vercel env run -e development -- <cmd>` there. The repo root is linked to `qingqi-dev`.
- Every user row is isolated by row level security on `app.user_id`. Read and write user tables only inside `withUser(db, userId, …)` (`src/assistant/db/with-user.ts`); global tables (users, passkeys, sessions, invites) use `asAssistantApp`. A new user table needs `SELECT isolate_user_table('"<table>"');` in its migration and a seeded row in `user-isolation.test.ts`.
- Migrations: change `src/assistant/db/schema.ts`, run `pnpm assistant:generate`; write SQL drizzle cannot generate with `pnpm exec drizzle-kit generate --custom --name <name>`. Vercel runs them on preview and production builds. Previews use the Neon branch `preview`, which `assistant-reset-preview-db.yml` resets from production every day, without sign-in sessions, mail accounts and push subscriptions.
- Crons: add the route under `src/app/api/cron/`, build it with `makeUserCronHandler`, and list it in `vercel.json`. The proxy lets `/api/cron/*` through without a Referer; the handler checks `CRON_SECRET`.
- Mail: `src/assistant/mail/`. IMAP goes through the `MailboxSession` interface (`imap/types.ts`); `imapflowConnector` is the real one, `createFakeMailServer` the in-memory one for tests. Never test against a real mailbox. Sync reads only (`BODY.PEEK`, read-only `EXAMINE`); the first sync of a folder stores no mail and puts the cursor at the newest UID. After each sync, `onNewMail` in `syncUserMail` classifies the queue: `live` mail without a classification.
- Local OAuth: Google and Microsoft accept only `https://assistant.qingqi.dev` and `http://localhost:3000` callbacks, so run `vercel env run -e development -- env ASSISTANT_PORT=3000 pnpm dev` to get the client ids.
- Classification: `src/assistant/classify/`. The prompt wording is only in `classify-prompt.ts` (raise its `version` when it changes), and the truth table that maps facts to a bucket only in `decide-bucket.ts`. `vercel env run -e development -- pnpm eval classify` scores the synthetic fixtures; `filed-mail.eval.ts` scores mail the user already filed, and needs `ASSISTANT_EVAL_USER_ID` and the production env (see the file).
- Digest: `src/assistant/digest/`. The hourly cron `build-digests` builds a user's digest from their digest hour on (local time, `due-digest-date.ts`) once per local day; open `act` items carry over until `done_at` is set. Sonnet arranges it (`digest-prompt.ts`, raise its `version` when it changes); `arrange-digest.ts` falls back to code order, so a digest is never skipped. Closing items runs `onItemsClosed` (`digest-handlers.ts`): the hook for mailbox writes. Web Push needs both VAPID env vars; the service worker registers in production builds only, so push cannot be tried under `pnpm dev`.
- Mailbox writes: `src/assistant/mail/tidy/`. Only with `user_settings.mailbox_writes` on, and only for mail classified after `mailbox_writes_since` (or mail the app wrote to before). `plan-mailbox-writes.ts` decides what each mail gets; `writeMailboxes` runs after classification in `onNewMail` and after `onItemsClosed`, keeps its progress in `mail_write_states`, and records failures on `mail_accounts.write_error_*`. A move updates `mail_messages.folder_id`, `uid` and `uid_validity` (`uid_validity` 0: the new UID is unknown, search by Message-ID). Never delete; MOVE only, no copy-and-expunge fallback.
